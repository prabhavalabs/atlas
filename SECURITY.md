# Security policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use GitHub's private vulnerability reporting feature from the repository **Security** tab and include:

- affected component or document;
- reproducible steps or proof of concept;
- likely impact;
- suggested mitigation, if known;
- whether any disaster information, administrator account, or source credential may be exposed.

The maintainers will acknowledge a complete report, assess severity, coordinate a fix, and publish an advisory when appropriate. Please avoid accessing data that is not yours, disrupting public services, or disclosing the issue before a remediation window has been agreed.

## Supported versions

Atlas has not published a production version. During planning and pre-release development, security fixes are made on the default branch. A supported-version table will be added before the first stable release.

## Safety-sensitive content issues

Incorrect or misleading public disaster information is a content-safety issue rather than a software vulnerability. Use the private channel if public disclosure could cause harm; otherwise use the dedicated correction issue template.
